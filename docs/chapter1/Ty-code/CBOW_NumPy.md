# 从零实现 Word2Vec 的 CBOW：NumPy 版原理与反向传播

本文通过一个小型英文语料，使用 NumPy 从零实现 Word2Vec 中的 CBOW（Continuous Bag of Words）模型。内容按照模型实际运行的顺序展开：先构造训练样本，再完成前向计算，随后推导反向传播，最后进行参数更新并观察训练结果。

阅读时可以始终围绕一个问题：**给定中心词周围的上下文，模型如何把这些词转换成一个概率分布，并逐步提高正确中心词的预测概率？**

---

## 1. CBOW 要解决什么问题？

CBOW 的任务是根据一个词的上下文预测该词本身。这里的“上下文”包括中心位置左侧和右侧的词，因此模型能够同时利用目标词前后的信息。

以语料中的句子为例：

> The quick brown fox jumps over the lazy dog.

假设当前要预测的中心词是 `brown`，窗口大小设为 2，那么模型会取中心词左侧最多两个词，以及右侧最多两个词：

- 上下文：`the`、`quick`、`fox`、`jumps`
- 目标词：`brown`

模型将四个上下文词对应的词向量取平均，再根据平均向量预测中心词。

### 1.1 为什么叫 Bag of Words？

CBOW 会把上下文词向量聚合成一个平均向量。由于平均运算不受输入顺序影响，`the、quick、fox、jumps` 与 `fox、the、jumps、quick` 得到的隐藏表示完全相同。

因此，在这个模型中，上下文词的具体排列顺序不会直接影响预测结果。不过，**词出现的次数仍然会影响平均结果**：如果某个词在上下文中出现两次，它的词向量就会参与两次平均。

CBOW 学习的条件概率可以写成：

\[
P(w_t\mid \text{上下文词})
\]

其中，\(w_t\) 表示待预测的中心词。模型的目标是让真实中心词在预测分布中获得尽可能高的概率。

### 1.2 CBOW 与 n-gram 的区别

CBOW 使用中心位置左右两侧的上下文预测中心词。例如，预测 `brown` 时，`fox` 和 `jumps` 虽然位于它的右侧，仍然会参与预测。

自回归语言模型中的 \(n\)-gram 则通常根据目标词之前的历史词预测下一个词。以 trigram 为例，预测 `brown` 时只使用 `the quick`，并且保留历史词的顺序。

两者在上下文范围和顺序处理方式上有所不同：

| 模型 | 预测目标 | 使用的上下文 | 是否保留词序 |
| --- | --- | --- | --- |
| CBOW | 当前中心词 | 中心词左右两侧的词 | 否，聚合时不保留顺序 |
| Trigram | 下一个词 | 目标词之前的两个词 | 是 |

### 1.3 本实验的基本设置

| 参数 | 取值 | 含义 |
| --- | ---: | --- |
| Window Size | 2 | 从中心位置向左、向右各最多取两个词 |
| Embedding Dimension \(d\) | 100 | 每个词向量包含 100 个坐标 |
| Vocabulary Size \(V\) | 25 | 整份语料中不同词的数量，也是输出类别数 |
| Context Length \(C\) | 主要示例为 4 | 当前样本实际包含的上下文词数，重复出现的词也计入 |

这里需要区分窗口大小和上下文长度：窗口大小固定为 2，但句首、句尾的词无法获得完整的左右上下文，因此实际的 \(C\) 可能小于 4。

### 1.4 如何从语料生成训练样本？

代码通过三个函数完成数据预处理：

1. `preprocess_corpus()`：将语料文件中的每一行视为一个独立句子，统一转换为小写，并提取连续的英文字母。
2. `build_vocab()`：按照词语首次出现的顺序，为词汇表中的每个词分配唯一 ID。
3. `generate_training_data()`：遍历每个句子中的每个词，将当前位置作为目标词，并从其左右两侧截取上下文。遇到句子边界时，窗口会自动裁剪，同时排除目标词本身。

例如，第一句中 `brown` 的上下文是 `the、quick、fox、jumps`。而句首的 `the` 左侧没有其他词，因此它的上下文只有 `quick` 和 `brown`。

实验语料共包含八个句子、65 个词位置。每个词位置都会生成一条训练样本，因此最终得到 65 条样本。

## 2. CBOW 模型的整体计算流程

理解 CBOW 的关键，是跟踪数据在模型中的形状变化。对于本例，输入上下文包含 4 个词，词汇表大小为 25，词向量维度为 100。一次前向传播可以概括为：

\[
(4,25)
\longrightarrow
(4,100)
\longrightarrow
(100,)
\longrightarrow
(25,)
\longrightarrow
\text{标量损失}
\]

各阶段的含义如下：

| 阶段 | 计算结果 | 形状 | 含义 |
| --- | --- | --- | --- |
| 输入 | One-hot 矩阵 \(X\) | \((4,25)\) | 表示 4 个上下文词 |
| Embedding Lookup | 上下文词向量 | \((4,100)\) | 每个上下文词对应一个 100 维向量 |
| Mean Pooling | 隐藏表示 \(h\) | \((100,)\) | 对 4 个词向量逐坐标求平均 |
| 输出层 | Logits \(z\) | \((25,)\) | 为词汇表中的 25 个候选词打分 |
| Softmax + Cross Entropy | 损失 \(L\) | 标量 | 衡量真实中心词的预测误差 |

接下来沿着这条计算路径，逐步解释每个环节。

---

## 3. 输入层：从 One-Hot 到词向量

### 3.1 One-Hot 矩阵如何表示上下文？

假设词汇表大小为 \(V\)，某个词的 ID 为 \(i\)。可以用一个 \(V\) 维 One-Hot 行向量表示它：

\[
e_i\in\mathbb{R}^{1\times V}
\]

这个向量只有第 \(i\) 个位置为 1，其余位置均为 0。

本例中，四个上下文词的 ID 为：

```python
[0, 1, 3, 4]
```

目标词 `brown` 的 ID 为 `2`。将四个上下文词的 One-Hot 向量按行堆叠，就得到一个形状为 \((4,25)\) 的矩阵 \(X\)。

### 3.2 为什么 One-Hot 乘以嵌入矩阵等价于查表？

定义输入嵌入矩阵：

\[
W_{\mathrm{in}}\in\mathbb{R}^{V\times d}
\]

其中，每一行对应一个词，每一列对应词向量的一个坐标。词 ID 决定从矩阵中读取哪一行。

对于 ID 为 \(i\) 的词，One-Hot 向量与输入嵌入矩阵相乘：

\[
e_iW_{\mathrm{in}}=W_{\mathrm{in}}[i,:]
\]

原因很直接：One-Hot 向量只有第 \(i\) 个位置为 1，因此矩阵乘法最终只会保留 \(W_{\mathrm{in}}\) 的第 \(i\) 行。

将 \(C\) 个上下文词的 One-Hot 向量堆叠成矩阵 \(X\)，便有：

\[
XW_{\mathrm{in}}
=
\begin{bmatrix}
W_{\mathrm{in}}[c_1,:]\\
\vdots\\
W_{\mathrm{in}}[c_C,:]
\end{bmatrix}
\in\mathbb{R}^{C\times d}
\]

其中，\(c_j\) 表示上下文中第 \(j\) 个位置的词 ID。

本例的矩阵形状为：

\[
(4,25)\times(25,100)=(4,100)
\]

也就是说，四个上下文词最终被转换成四个 100 维词向量。

实际训练时，无须真的构造 One-Hot 矩阵再执行乘法。直接根据词 ID 从嵌入矩阵中取出对应行即可，这就是 Embedding Lookup。代码中的实现为：

```python
self.W_in[context_ids, :]
```

`show_example()` 则专门构造 One-Hot 矩阵，并验证矩阵乘法与直接查表得到的结果逐元素相同。

### 3.3 输入嵌入矩阵的含义

\[
W_{\mathrm{in}}\in\mathbb{R}^{V\times d}
\]

可以理解为整张词汇表的词向量集合。每个词 ID 对应其中一行，这一行的 \(d\) 个浮点数就是该词当前的向量表示。

这些向量并非预先确定，而是模型训练过程中持续更新的参数。只要某个词出现在当前样本的上下文中，它对应的输入向量就会参与前向计算，并在反向传播时接收梯度。中心词 ID 则用于指定输出层中正确的预测类别。

代码中的 `initialize_parameters()` 负责初始化参数：

- `W_in` 和 `W_out` 的元素均从均值为 0、标准差为 \(1/\sqrt{d}\) 的正态分布中采样。
- 输出偏置 `b` 初始化为全零向量。

## 4. 隐藏层：对上下文词向量求平均

经过 Embedding Lookup 后，模型得到一个形状为 \((C,d)\) 的矩阵。每一行是一个上下文词的向量表示。

CBOW 使用平均池化（Mean Pooling）将这些向量合并为一个 \(d\) 维隐藏表示：

\[
h=\frac{1}{C}\sum_{j=1}^{C}v_j
\]

其中，\(v_j=W_{\mathrm{in}}[c_j,:]\) 表示上下文中第 \(j\) 个位置的词向量。

对于 `brown` 这个示例：

\[
h=
\frac{
v_{\mathrm{the}}+
v_{\mathrm{quick}}+
v_{\mathrm{fox}}+
v_{\mathrm{jumps}}
}{4}
\]

这样处理有两个直接作用。

首先，输出层只需要接收一个 \(d\) 维向量，而不是数量可变的多个上下文词向量。无论当前样本包含两个、三个还是四个上下文词，平均之后的隐藏表示始终是 \(d\) 维。

其次，除以实际上下文词数 \(C\)，可以让每个上下文位置以相同权重参与表示，避免仅仅因为上下文词更多，就使向量各坐标的数值整体累加得更大。

在代码中，这一步由下面的操作完成：

```python
context_vectors.mean(axis=0)
```

`axis=0` 表示沿着上下文位置这一维求平均，也就是对矩阵的每一列分别计算均值。

公式中将 \(h\) 写成行向量。对于本例，NumPy 中的 `h` 是形状为 `(100,)` 的一维数组。训练前，它的前四个坐标约为：

```python
[0.03686, -0.02695, 0.05196, 0.02390]
```

`CBOW.forward()` 负责生成隐藏表示，`show_example()` 会打印它的形状和部分数值。

## 5. 输出层：为整个词汇表中的候选词打分

隐藏表示 \(h\) 已经汇总了上下文信息。接下来，模型需要根据它判断词汇表中的哪个词最可能是中心词。

为此，定义输出权重矩阵和偏置向量：

\[
W_{\mathrm{out}}\in\mathbb{R}^{d\times V},
\qquad
b\in\mathbb{R}^{V}
\]

输出层首先计算：

\[
z=hW_{\mathrm{out}}+b
\]

其中，\(z\in\mathbb{R}^{V}\) 是输出层得到的原始分数，也称为 Logits。第 \(j\) 个候选词对应的分数为：

\[
z_j=
\sum_{i=1}^{d}h_i(W_{\mathrm{out}})_{ij}+b_j
\]

可以从三个方面理解这些参数：

- \(W_{\mathrm{out}}\) 的第 \(j\) 列负责根据隐藏表示计算候选词 \(j\) 的分数。
- \(b_j\) 是候选词 \(j\) 对应的可训练偏置。
- \(z_j\) 是模型对候选词 \(j\) 给出的原始分数，数值越大，经过 Softmax 后通常对应越高的预测概率。

本例中，NumPy 执行的运算为：

```python
logits = h @ self.W_out + self.b
```

其形状变化为：

\[
(100,)@(100,25)+(25,)=(25,)
\]

因此，输出层会为词汇表中的 25 个词分别计算一个分数。

---

## 6. Softmax 与交叉熵损失

Logits 只是原始分数，不能直接解释为概率。模型需要通过 Softmax 将它们转换成一个总和为 1 的概率分布：

\[
p_j=
\frac{\exp(z_j)}
{\sum_{k=1}^{V}\exp(z_k)}
\]

因此：

\[
\sum_{j=1}^{V}p_j=1
\]

设目标词的 ID 为 \(t\)，其 One-Hot 标签为 \(y\)。单个训练样本的交叉熵损失为：

\[
L=-\sum_{j=1}^{V}y_j\log p_j
=-\log p_t
\]

由于真实标签只有目标词对应的位置为 1，损失最终只取目标词的预测概率 \(p_t\)。

**目标词的预测概率越高，交叉熵损失就越低。** 因此，训练的直接目标就是不断调整模型参数，使真实中心词获得更高的预测概率。

### 6.1 为什么要进行数值稳定处理？

直接计算 \(\exp(z_j)\) 时，如果 Logits 数值较大，指数运算可能超出浮点数的表示范围。为避免这种情况，代码先令：

\[
m=\max_j z_j
\]

再将所有 Logits 同时减去 \(m\)。Softmax 可以改写为：

\[
p_j=
\frac{\exp(z_j-m)}
{\sum_{k=1}^{V}\exp(z_k-m)}
\]

分子和分母同时乘以 \(e^{-m}\)，不会改变最终概率。与此同时，所有指数的输入都不大于 0，从而降低数值溢出的风险。

代码进一步直接计算对数概率：

\[
\log p_j
=
(z_j-m)
-
\log\sum_{k=1}^{V}\exp(z_k-m)
\]

然后再通过指数运算得到概率。计算损失时，直接使用目标词对应的 `log_probs[target_id]`，可以避免先得到极小概率、再对其取对数时出现概率下溢为 0 的问题。

### 6.2 本例的初始预测

对于 `brown` 这个训练样本，模型在训练前得到：

| 指标 | 数值 |
| --- | ---: |
| 目标词 Logit：\(z_{\mathrm{brown}}\) | \(-0.024883\) |
| 目标词预测概率：\(p_{\mathrm{brown}}\) | \(0.038962\) |
| 单样本交叉熵损失：\(L\) | \(3.245167\) |

这里的损失是针对 `brown` 这一条样本计算的。它与后文报告的全语料平均损失并不相同。

代码中的 `CBOW.forward()` 负责计算 `shifted`、`log_probs` 和 `probs`；`compute_loss()` 则通过 `-log_probs[target_id]` 取得当前样本的交叉熵损失。

## 7. 反向传播：梯度如何传回两组嵌入参数？

前向传播完成后，模型已经得到当前样本的损失 \(L\)。反向传播需要回答一个问题：**应该如何调整 \(W_{\mathrm{in}}\)、\(W_{\mathrm{out}}\) 和 \(b\)，才能降低损失？**

下面按照计算图的反方向，从损失开始，依次推导各个参数的梯度。

为方便与 NumPy 代码对应，以下将各层梯度分别记为 \(g_z\) 和 \(g_h\)。在本实验中，`dz`、`db` 和 `dh` 都以一维数组表示。

### 7.1 从交叉熵损失求 Logits 的梯度

将 Softmax 代入交叉熵损失，可以得到：

\[
L=-z_t+\log\sum_{k=1}^{V}e^{z_k}
\]

对第 \(j\) 个 Logit 求偏导：

\[
\begin{aligned}
\frac{\partial L}{\partial z_j}
&=-\mathbf{1}[j=t]
+\frac{e^{z_j}}{\sum_{k=1}^{V}e^{z_k}}\\
&=p_j-y_j
\end{aligned}
\]

因此，Logits 的梯度为：

\[
g_z=\nabla_z L=p-y
\]

其形状为 `(V,)`，也就是 `(25,)`。

对于本例，目标词是 `brown`，所以：

\[
g_z[\mathrm{brown}]
=
p_{\mathrm{brown}}-1
\approx -0.961038
\]

其余词对应的梯度均等于各自的预测概率。

这一步在代码中非常简洁：

```python
dz = result.probs.copy()
dz[target_id] -= 1.0
```

也就是说，先复制预测概率向量，再将真实目标词所在位置减去 1，便得到 \(p-y\)。

### 7.2 从 Logits 求输出权重和偏置的梯度

输出层的计算式为：

\[
z_j=\sum_{i=1}^{d}h_i(W_{\mathrm{out}})_{ij}+b_j
\]

根据链式法则，对输出权重中的元素求偏导：

\[
\frac{\partial L}
{\partial (W_{\mathrm{out}})_{ij}}
=
g_{z,j}h_i
\]

对偏置求偏导：

\[
\frac{\partial L}{\partial b_j}=g_{z,j}
\]

因此，矩阵形式为：

\[
\nabla_{W_{\mathrm{out}}}L=h^\top g_z
\]

\[
\nabla_b L=g_z
\]

其中，\(h^\top g_z\) 是一个外积，形状为 \((d,V)\)，即本例中的 `(100, 25)`；偏置梯度的形状为 `(V,)`，即 `(25,)`。

直观地看，隐藏表示中的每个坐标 \(h_i\) 都参与了全部 \(V\) 个候选词的打分计算。因此，输出权重矩阵中每一列都需要根据对应候选词的梯度进行更新。

### 7.3 从 Logits 将梯度传回隐藏层

输出层还需要将损失的梯度继续传回隐藏表示 \(h\)。

由输出层计算式可得：

\[
\frac{\partial L}{\partial h_i}
=
\sum_{j=1}^{V}
g_{z,j}(W_{\mathrm{out}})_{ij}
\]

写成矩阵形式：

\[
g_h=\nabla_h L=g_zW_{\mathrm{out}}^\top
\]

因此，\(g_h\) 的形状为 `(d,)`，即 `(100,)`。

至此，输出层相关的梯度已经全部得到：

| 梯度 | 计算方式 | 形状 |
| --- | --- | --- |
| `dz` | \(p-y\) | \((V,)\) |
| `dW_out` | \(h^\top g_z\) | \((d,V)\) |
| `db` | \(g_z\) | \((V,)\) |
| `dh` | \(g_zW_{\mathrm{out}}^\top\) | \((d,)\) |

对应的 NumPy 代码为：

```python
dW_out = np.outer(result.h, dz)
db = dz
dh = dz @ self.W_out.T
```

### 7.4 从隐藏层将梯度传回输入嵌入矩阵

隐藏表示是所有上下文词向量的平均值：

\[
h=\frac{1}{C}\sum_{j=1}^{C}v_j
\]

因此，对于上下文中的任意位置 \(j\)，都有：

\[
\frac{\partial h_i}{\partial v_{j,i}}
=
\frac{1}{C}
\]

根据链式法则，该位置对应的词向量梯度为：

\[
\nabla_{v_j}L=\frac{g_h}{C}
\]

这里最需要注意的是：**同一个词 ID 可能在上下文中出现多次，而每次出现都对应一次查表操作，也都需要接收一份梯度。**

假设词 ID 为 \(r\)，它在上下文中的位置集合为：

\[
\{j\mid c_j=r\}
\]

那么，输入嵌入矩阵第 \(r\) 行的梯度就是这些位置所接收梯度的累加：

\[
\nabla_{W_{\mathrm{in}}[r,:]}L
=
\sum_{j=1}^{C}
\mathbf{1}[c_j=r]\frac{g_h}{C}
\]

其中，\(\mathbf{1}[c_j=r]\) 是指示函数：当第 \(j\) 个上下文词的 ID 等于 \(r\) 时取 1，否则取 0。

对于当前的 `brown` 样本，四个上下文词 `the、quick、fox、jumps` 各出现一次，因此对应的四行各自增加：

\[
\frac{g_h}{4}
\]

由于 `brown` 本身没有出现在这条样本的上下文中，所以本次反向传播不会更新它在 `W_in` 中对应的那一行。如果某个词在上下文中出现两次，那么它对应的嵌入行就会累加两份 \(g_h/C\)。

同样，句首或句尾的样本可能只有两个上下文词。此时 \(C=2\)，每次出现所接收的梯度就是 \(g_h/2\)，而不是固定的 \(g_h/4\)。

代码通过循环完成这一累加过程：

```python
dW_in = np.zeros_like(self.W_in)

for word_id in context_ids:
    dW_in[word_id] += per_context_gradient
```

每次执行 `+=` 时，都会在原有梯度基础上继续累加。因此，即使同一个词 ID 出现多次，也不会覆盖之前已经累计的梯度。

### 7.5 用数值梯度检查反向传播

手动推导出梯度后，还可以通过数值方法检查推导和代码实现是否一致。本实验使用中心差分法（Central Difference）。

对于某个标量参数 \(\theta_i\)，分别将它增加和减少一个很小的扰动量 \(\varepsilon\)，重新执行前向传播，再计算：

\[
g_i^{\mathrm{num}}
\approx
\frac{
L(\theta_i+\varepsilon)-L(\theta_i-\varepsilon)
}{
2\varepsilon
},
\qquad
\varepsilon=10^{-5}
\]

将这个数值梯度与反向传播得到的解析梯度进行比较。如果两者非常接近，就说明梯度推导和实现基本一致。

代码中的 `gradient_check()` 从 `W_in`、`W_out` 和 `b` 中抽查 7 个标量参数。每次扰动参数后，都会在检查结束时恢复原值，避免影响后续检查。

本次检查的部分结果如下：

- `W_in[0, 0]` 的解析梯度和数值梯度均约为 \(-0.01506209\)。
- `W_in[2, 0]` 在本例中的两种梯度均为 0。
- 所有抽查项中的最大绝对误差为 \(1.40\times10^{-11}\)。

这一结果说明，本次实验中的反向传播实现与数值梯度高度一致。

## 8. 参数更新：使用 SGD 训练模型

得到各个参数的梯度后，就可以更新模型参数。本实验采用逐样本随机梯度下降（Stochastic Gradient Descent，SGD）。

设学习率为 \(\eta=0.1\)，则一次参数更新为：

\[
\begin{aligned}
W_{\mathrm{in}}
&\leftarrow
W_{\mathrm{in}}-\eta\nabla_{W_{\mathrm{in}}}L,\\
W_{\mathrm{out}}
&\leftarrow
W_{\mathrm{out}}-\eta\nabla_{W_{\mathrm{out}}}L,\\
b
&\leftarrow
b-\eta\nabla_b L.
\end{aligned}
\]

本实验每轮训练都会先打乱全部 65 条样本的顺序，然后逐条执行以下步骤：

1. 根据当前样本的上下文进行前向传播。
2. 计算当前样本的交叉熵损失。
3. 通过反向传播计算 `W_in`、`W_out` 和 `b` 的梯度。
4. 根据 SGD 更新式调整三个参数。

代码中的 `train()` 会先计算完本次更新所需的梯度，再执行三项参数更新。

### 8.1 如何记录每轮的平均损失？

为了观察训练效果，程序在训练开始前以及每轮结束后，都会调用 `mean_loss()`，使用当前固定的模型参数重新计算全部 65 条样本的平均交叉熵。

因此：

- `loss_history[0]` 表示训练开始前的全语料平均损失。
- `loss_history[e]` 表示第 \(e\) 轮训练结束后的全语料平均损失。

终端会打印第 1 轮、每 25 轮以及最后一轮的损失记录。

### 9.3 提取词向量并计算余弦相似度

训练完成后，可以直接从输入嵌入矩阵中取出某个词的向量。例如：

```python
model.W_in[word_to_id["brown"]]
```

得到的是训练后的 `brown` 词向量，形状为 `(100,)`。

如果希望比较两个词向量的方向是否接近，可以计算余弦相似度：

\[
\operatorname{cos}(u,v)
=
\frac{u\cdot v}
{\lVert u\rVert_2\lVert v\rVert_2}
\]

其中，\(u\) 和 \(v\) 是两个词向量，分子为向量点积，分母为两个向量的 L2 范数之积。余弦相似度越接近 1，表示两个向量的方向越接近。

代码中的 `cosine_similarity()` 用于计算两个非零向量的余弦相似度。`main()` 会逐词计算它们与 `brown` 的相似度，排除 `brown` 自身后，按得分从高到低取前五个词。

本次实验得到的结果为：

| 排名 | 词语 | 与 `brown` 的余弦相似度 |
| ---: | --- | ---: |
| 1 | red | 0.394320 |
| 2 | house | 0.251189 |
| 3 | field | 0.205819 |
| 4 | lazy | 0.169172 |
| 5 | river | 0.146971 |

需要注意，本实验使用的只是规模很小的人工语料。因此，这些相似度结果主要用于观察训练机制，帮助理解模型如何形成词向量。若要据此得出可靠的语言学结论，还需要更有代表性的语料和进一步的实证检验。

## 11. 建议的代码阅读顺序

如果希望结合代码理解 CBOW，可以按照模型的数据流依次阅读，而不必一开始就通读整个脚本。

**第一步：理解训练样本如何生成。**

先阅读 `preprocess_corpus()`、`build_vocab()` 和 `generate_training_data()`。尝试根据第一句语料，手动写出以 `brown` 为目标词的训练样本，再找出句首 `the` 对应的边界样本。这样可以先弄清楚模型究竟接收什么输入。

**第二步：跟踪一次前向传播。**

阅读 `show_example()`、`CBOW.forward()` 和 `compute_loss()`。重点关注数据形状如何变化：

\[
(4,100)
\longrightarrow
(100,)
\longrightarrow
(25,)
\longrightarrow
\text{标量损失}
\]

可以在纸上写出每一步对应的矩阵运算，再对照代码确认。

**第三步：沿计算图反向追踪梯度。**

重点阅读 `CBOW.backward()`，按照下面的顺序理解梯度如何逐层传递：

\[
dz
\longrightarrow
\begin{cases}
dW_{\mathrm{out}},\ db,\ dh
\end{cases}
\longrightarrow
dW_{\mathrm{in}}
\]

建议重点跟踪 `W_in[0, 0]` 这一项，并结合 `gradient_check()` 对照解析梯度和数值梯度。

**第四步：观察参数更新与训练结果。**

阅读 `train()`，弄清楚一次 SGD 更新具体修改了哪些参数，以及每轮平均损失如何计算。最后使用 `CBOW.predict()` 和 `cosine_similarity()`，观察同一个上下文在训练前后的预测变化，以及训练后词向量之间的相似度。

完成这四步后，就能够把 CBOW 的数据预处理、前向传播、损失计算、反向传播和参数更新串联起来，形成对整个训练过程的完整认识。
